Projet full-stack · Laravel · Flutter · MySQL

Le paiement marchand par QR code, du serveur au téléphone.

IvoirePay réunit une API REST Laravel, un back-office web d'exploitation et une application mobile Flutter pour clients et commerçants. Un QR code par commerçant, un PIN pour confirmer, cinq portefeuilles mobile money.

Deux captures, toutes deux réelles

Aucune maquette : la landing est capturée avec Playwright, l'accueil mobile sur un appareil Android avec un compte de démonstration fictif. Cliquez pour agrandir.

Architecture

Un backend, deux interfaces

Le téléphone parle JSON à l'API avec un jeton Sanctum ; l'équipe d'exploitation passe par le back-office web. La logique métier vit dans des services partagés.

  1. MobileApplication FlutterRiverpod · go_router · Dio
  2. HTTPAPI REST LaravelSanctum · validation · /api/*
  3. MétierServicespaiement · QR · notifications · SMS · jobs
  4. ORMEloquentverrous de ligne · transactions SQL
  5. DonnéesMySQLutilisateurs · marchands · transactions · retraits

Back-office web

Blade sur /admin, session réservée au rôle administrateur : KYC, transactions et exports, retraits, utilisateurs, notifications groupées.

Intégrations externes

Yengapay (agrégateur mobile money, webhook signé HMAC) et Africa's Talking (SMS / OTP). Simulées dans la configuration fournie : aucun paiement réel.

Fonctionnalités

Ce qui est implémenté

Client

  • Inscription par téléphone et OTP
  • Connexion par PIN, option biométrique
  • Scan du QR, choix du portefeuille, confirmation par PIN
  • Historique, détail et reçu PDF

Commerçant

  • Dossier KYC avec pièces justificatives
  • QR code statique après validation
  • Tableau de bord et graphique sur 7 jours
  • Retraits protégés par PIN

Fiabilité des paiements

  • Webhooks signés et idempotents
  • Crédit du solde sous verrou de ligne
  • Remboursement de retrait effectué une seule fois
  • Documents KYC privés, URL signées
